## Candidate and release record

The owning ticket retains candidate source/index/dirty manifests, specification digest, exact
base/head identities, check outcomes and full proposed-change review. Source tests, semantic
scenario review, actual clients and application integration are separate evidence classes. A
versionless shared source file cannot carry its own final commit SHA without circular updates;
record the authorized commit in the release/consumer gitlinks and external ticket evidence.

Retain the initial README title, original ignore configuration and pre-existing ignored IDE
module file. Exclude tool environments, databases, local evidence and disposable outputs from
staging. Run the [contributor gates](../CONTRIBUTING.md), then follow the separate
[release/availability boundary](../docs/upgrades.md#release-and-evidence-boundary). A prepared
working tree is reviewable but not a committed/published release or proof of upstream freshness.
